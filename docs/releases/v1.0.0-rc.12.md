## Unauthenticated install path (demo hosts)

On a host without GHCR credentials:

```bash
sha256sum -c araf-v1.0.0-rc.12-oci-tarballs.sha256
# Offline config verification: the config blob named in the tarball must
# equal the bff-config line in araf-v1.0.0-rc.12-digests.txt.
tar -xOf araf-bff-v1.0.0-rc.12.oci.tar manifest.json | jq -r '.[0].Config'
# -> blobs/sha256/a22458df7ced503bbda9e69e45ec559b5881a63d8f8849ef24721bb8918c5edc
load_output=$(docker load -i araf-bff-v1.0.0-rc.12.oci.tar)
echo "$load_output"
loaded=$(printf '%s\n' "$load_output" | sed -n 's/^Loaded image ID: //p')
docker tag "$loaded" ghcr.io/o3kio/araf-bff:v1.0.0-rc.12
```

Repeat the load/verify/tag cycle for the two console tarballs
(`tenant-console`, `operator-console`; their config digests are the
`tenant-console-config` / `operator-console-config` lines). The tag step is
what makes the digest-pinned release Compose references resolve locally —
there is no pull to fall back to. The loaded image is restored under its
index digest (verified against the release docker engine), so the offline
Compose `.env` keeps the index digest pins from the main `digests.txt`
lines; `docker image inspect ghcr.io/o3kio/araf-bff@sha256:bc717ecdbbbf3ea673efe168c90419936677d644aa0ae25af4eb84906cd744ba`
must resolve after tagging. Config-digest verification before tagging is not
optional; it proves the tarball content is exactly the attested image. Then
proceed with the Compose path in
[docs/operator/installation.md](../operator/installation.md).

Verify checksums with `sha256sum -c` against the downloaded assets and
re-resolve image digests as described in `VERIFY.md` (inside the deploy
tarball) and [docs/operator/installation.md](../operator/installation.md).

## Known limitations

- **GHCR tags are not platform-immutable.** The published digests are the
  cryptographic/policy authority and the attestation subjects, but the
  registry does not enforce tag immutability; always pin and verify by
  `@sha256:` digest.
- **Keycloak / external IdP is not part of the Araf bundle.** Araf requires
  a supported external OIDC provider with one confidential client per
  surface; identity-provider deployment, TLS certificates and DNS remain
  deployment-boundary concerns.
- **1h upstream token TTL is an accepted deviation.** The O3K/OIDC upstream
  token lifetime of one hour is accepted for this demo phase; longer-running
  operator sessions re-authenticate on expiry. BFF session custody and
  rotation behavior are unchanged.
