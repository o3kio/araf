# M12 — Production authentication and security hardening

**Delivery gate:** MVP Security Gate  
**Depends on:** M3-M11 sufficiently integrated

## Goal

Turn the prototype/real-integration BFF boundary into a defensible production browser security architecture and prove tenant/operator isolation.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M12-security-hardening.md`](../blob/main/prompts/M12-security-hardening.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- browser never receives persistent reusable O3K refresh/access credentials by design,
- tenant/operator isolation is proven by negative tests,
- session fixation/logout/expiry behavior is tested,
- CSRF attacks are rejected,
- strict CSP passes with shipped assets,
- sensitive values are absent from logs/browser storage,
- security evidence is summarized in `docs/engineering/security-evidence.md`.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
