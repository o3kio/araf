# M9 — Operator platform, regions and provider health

**Delivery gate:** MVP  
**Depends on:** M2, M3, M4, M6; current O3K operator/provider contracts

## Goal

Create an operator experience for platform/customer/resource oversight without data-plane shell access and without exposing operator capabilities through the Tenant Console.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M9-operator-platform.md`](../blob/main/prompts/M9-operator-platform.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- operator can identify region/provider degradation and inspect associated operations without data-plane access,
- organization/project lookup is scope/authorization safe,
- tenant credentials/session cannot use operator endpoints,
- capacity/health is based on authoritative O3K control-plane data,
- no unsupported privileged action is fabricated.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
