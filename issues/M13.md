# M13 — Accessibility, i18n, density and cross-browser closure

**Delivery gate:** MVP Quality Gate  
**Depends on:** M1-M11 core flows available

## Goal

Close the MVP as an enterprise console usable with keyboard/assistive technology, ready for localization, and consistent across supported desktop browsers and density modes.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M13-accessibility-i18n.md`](../blob/main/prompts/M13-accessibility-i18n.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- critical flows meet the project WCAG 2.2 AA target with documented automated/manual evidence,
- no hard-coded unextractable user-facing strings in core runtime/pages,
- dates/numbers/currency are locale-safe,
- compact/comfortable modes do not break interactions,
- release-critical cross-browser tests pass.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
