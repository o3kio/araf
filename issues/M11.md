# M11 — Usage, quota and bounded cost awareness

**Delivery gate:** MVP  
**Depends on:** M7/M8 and authoritative upstream metering/quota data

## Goal

Make resource consumption understandable without turning Araf into an invoicing/accounting system or fabricating cost data.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M11-metering-usage.md`](../blob/main/prompts/M11-metering-usage.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- tenant can understand quota and available usage metrics,
- cost is shown only from authoritative price + usage data and is labeled as estimate when appropriate,
- no invoice/billing ledger has been invented,
- cross-project usage access is rejected,
- large date ranges are bounded server-side.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
