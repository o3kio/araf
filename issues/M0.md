# M0 — Repository bootstrap and deterministic quality gates

**Delivery gate:** Prototype  
**Depends on:** None

## Goal

Create the smallest production-quality mixed TypeScript/Rust workspace that can support two console applications, shared packages and two Rust BFF binaries without prematurely implementing product features.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M0-bootstrap.md`](../blob/main/prompts/M0-bootstrap.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- fresh checkout can install/build/test using documented commands,
- both Vite apps run independently,
- both Rust BFF binaries run independently,
- TypeScript is strict and CI fails on type/lint/test errors,
- Rust fmt/clippy/check/test passes,
- workspace boundaries match ADR 0001,
- no cloud tokens or fake cloud APIs have been introduced.

Use branch suggestion: `m0-repository-bootstrap`.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
