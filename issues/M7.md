# M7 — Real O3K tenant core-service integration

**Delivery gate:** MVP  
**Depends on:** M6 GO; M3-M6

## Goal

Bind the proven generic runtime to real supported O3K native contracts for a representative tenant cloud-service set without introducing compatibility/provider jargon.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M7-tenant-core.md`](../blob/main/prompts/M7-tenant-core.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- representative real O3K resources render through the same generic runtime used by fixtures,
- at least one real mutation returns/tracks canonical O3K Operation if supported upstream,
- no OpenStack service names/provider internals leak into native tenant UX,
- scope isolation tests exist,
- fixture/production adapter separation is explicit.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
