# M4 — Generic resource list/detail/relationship runtime

**Delivery gate:** Prototype  
**Depends on:** M1, M2, M3

## Goal

Prove that Araf can render high-quality cloud resources from descriptors rather than hard-coded per-service screens.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M4-resource-runtime.md`](../blob/main/prompts/M4-resource-runtime.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- three resource types render without service-specific page components,
- pagination is server bounded,
- relationship navigation preserves scope,
- untrusted resource strings are safely rendered,
- Problem Details/correlation UX works,
- generic runtime is demonstrably usable at prototype quality.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
