# M2 — Tenant/Operator shells and explicit scope context

**Delivery gate:** Prototype  
**Depends on:** M0, M1

## Goal

Build distinct Tenant and Operator application shells using shared packages while making scope/context obvious and preventing privilege-surface mixing.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M2-shells-context.md`](../blob/main/prompts/M2-shells-context.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- tenant/operator apps visibly differ by purpose but share the same design system,
- project/region switching is deterministic and testable,
- `Global` is modeled explicitly,
- direct route navigation retains scope,
- tenant application contains no operator route surface,
- critical shell navigation works with keyboard only.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
