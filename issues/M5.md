# M5 — Schema-driven create/edit/action flows

**Delivery gate:** Prototype  
**Depends on:** M4

## Goal

Prove that ordinary cloud mutations can be rendered from JSON Schema plus bounded presentation metadata without turning descriptors into executable programs.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M5-schema-actions.md`](../blob/main/prompts/M5-schema-actions.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- create flow is generated from schema/presentation metadata,
- server rejects invalid/unauthorized submissions,
- action produces an Operation,
- Advanced grouping works without provider-specific leakage,
- no arbitrary executable descriptor capability exists,
- keyboard/form error behavior is accessible.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
