# M1 — Araf design system foundation

**Delivery gate:** Prototype  
**Depends on:** M0

## Goal

Create the Araf-owned UI foundation that can support an enterprise cloud console without leaking the underlying component-library API through the product.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M1-ui-foundation.md`](../blob/main/prompts/M1-ui-foundation.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- `packages/ui` is the sole third-party UI import boundary,
- comfortable/compact mode is token-driven,
- semantic status and focus behavior is documented/tested,
- tenant/operator apps can consume the same primitives,
- automated accessibility checks pass for the implemented primitives.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
