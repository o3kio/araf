# M8 — Tenant governance, access, quota and audit

**Delivery gate:** MVP  
**Depends on:** M2, M3, M4; current O3K IAM/governance contracts

## Goal

Give delegated organization/project administrators enterprise-grade governance without exposing platform-operator authority.

## Architectural constraints

- Follow `AGENTS.md` and the accepted ADRs.
- Araf must not invent authoritative O3K cloud semantics or undocumented production endpoints.
- Fixture behavior must remain explicitly separated from production adapters.
- Tenant/provider/operator trust and vocabulary boundaries must remain intact.
- Implement only this phase; post-MVP features remain out of scope unless this issue explicitly requires a compatibility hook.

## Full implementation prompt

Use [`prompts/M8-tenant-governance.md`](../blob/main/prompts/M8-tenant-governance.md) as the implementation instruction and acceptance source of truth.

## Acceptance criteria

- delegated user can understand project access/quota/audit within authorized scope,
- forbidden project/resource access is rejected server-side,
- role names are not treated as permission truth,
- audit and operation histories remain distinct,
- secrets are not persisted in browser storage/logs.

## Required final evidence

The PR must contain the implementation report required by `AGENTS.md`, including tests, security/accessibility implications, upstream O3K gaps and explicitly deferred scope.
