# P3.6 — OpenStack CompatibilityOperations and reconciliation

## Goal
Provide truthful async UX for OpenStack without pretending OpenStack has O3K canonical Operations.

## Design constraints
A CompatibilityOperation is an Araf compatibility artifact used to correlate a requested action with authoritative OpenStack resource/task state. It is never authoritative for resource state.

## Implement
- durable-enough correlation journal as required for page reload/BFF restart;
- operation provenance (`openstack` compatibility versus `o3k` canonical) internally;
- poll/reconcile Nova/Neutron/Cinder/Glance state according to action/resource adapters;
- terminal success only from authoritative conditions;
- failure, timeout/unknown and recovery semantics;
- restart reconciliation so stale journal state cannot lie after process loss;
- scope-safe listing/detail and retention bounds;
- correlation/request IDs and links to resources;
- explicit inability to invent fine-grained steps when upstream exposes none.

## Acceptance
Create/start/stop/delete/volume/network operations remain truthful across reload and BFF restart, including real failure scenarios, and cannot override contradictory OpenStack resource truth.
