# P2.6 — Real Operator control-plane health and capacity

## Goal
Make the Operator Console useful for diagnosing O3K without data-plane shell access.

## Implement as supported by O3K
- platform/region/AZ health;
- installed service readiness;
- registered provider/controller health;
- bounded capacity summaries and saturation signals;
- project/scope lookup required for support;
- Operations and Audit correlation;
- explicit degraded/unknown states and timestamps.

## Security
Operator routes require explicit operator/system authorization. Never expose provider credentials or create SSH/kubectl/Ceph/provider-shell features.

## Acceptance
Representative provider/service degradation is visible and investigable from authoritative O3K control-plane data through the Operator Console.
