## Current Araf gaps to close

1. **Provider-neutral OIDC client behavior.** The BFF currently derives a Keycloak-style token URL (`.../protocol/openid-connect/token`) and supports separately configured authorization/userinfo URLs. Replace provider-specific endpoint construction with standards-based OIDC Discovery metadata (`authorization_endpoint`, `token_endpoint`, `userinfo_endpoint` when used), with issuer consistency and bounded network/config validation.
2. **Production configuration must fail closed.** Coordinate with #40. P2.1 cannot claim production identity while missing/malformed production configuration can silently select fixtures or localhost-style defaults.
3. **Real Operator BFF process evidence.** Run a real standards-based IdP -> Operator BFF -> O3K system-token/AuthContext -> authorized operator API journey, plus a tenant-negative path against the same real process boundary.
4. **Canonical context projection.** Verify the frontend/BFF current-user context shown to the application is derived from O3K native identity/scope truth, not IdP profile fields or fixture context.
5. **Session lifecycle.** Preserve logout/expiry/fixation/CSRF/state/PKCE protections. Refresh-token renewal is not required to change O3K semantics; if not implemented, external-token expiry must terminate the session cleanly and remain an explicit bounded behavior. Multi-replica/durable session storage belongs to P4.3 unless promoted separately.
