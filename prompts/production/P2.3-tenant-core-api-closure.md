# P2.3 — Native O3K tenant core API closure

## Goal
Make the agreed tenant IaaS core fully real through the existing generic Araf runtime.

## Required profile
- Compute server list/show/create/delete/start/stop;
- Image discovery required for creation;
- native compute offering/size discovery required for creation;
- Network list/show and required create-time selection semantics;
- Volume list/show and supported lifecycle/attachment reads/actions in current scope;
- real resource relationships where authoritative.

## Rules
- inspect current O3K API before coding;
- do not add service-specific React pages to bypass descriptor/runtime gaps;
- every async mutation follows canonical O3K Operation identity;
- server-side authorization is authoritative;
- pagination/filter/sort stays bounded;
- production returns explicit unsupported state rather than falling back to fixtures/501 hidden behind fake success.

## Acceptance
A real tenant can complete the supported VM/network/storage lifecycle through Araf using only O3K-native APIs and the generic runtime.
