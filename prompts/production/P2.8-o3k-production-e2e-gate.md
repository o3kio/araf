# P2.8 — Native O3K production convergence gate

## Goal
Prove Araf works as a real O3K cloud console with no production fixture dependency.

## Environment
Deploy real O3K + real supported providers + real standards-based IdP + Tenant Console/BFF + Operator Console/BFF using production configuration and the completed P12-IAM federation contract.

The environment must use the same configuration path intended for the supported production profile. Test-only insecure OIDC/HTTP exceptions do not count as production evidence.

## Required journeys

### Tenant
login -> OIDC callback -> O3K scope discovery -> choose project -> canonical `/identity/me` context -> list/create supported network/VM/storage -> follow canonical Operation -> inspect resource/relationships -> stop/start/delete -> quota/usage/audit where supported -> logout.

### Failure
trigger a real control-plane/provider failure -> canonical Operation fails -> Araf exposes structured reason/correlation without fake success.

### Isolation
Project A attempts Project B resource/Operation -> server-side O3K denial/non-disclosure. Manipulating project/scope identifiers in the browser or BFF request must not broaden authority.

### Operator
real operator login -> separate Operator BFF/session -> O3K system exchange/AuthContext -> authorized operator API -> inspect region/provider/service degradation -> correlate affected resources/Operations without data-plane shell.

The same real environment must prove that a normal tenant session/token cannot use the operator API even when the route is known.

### Credential/session custody
Inspect browser cookies/storage/network and BFF logs. No reusable IdP access/refresh token or native O3K token may be present in localStorage, sessionStorage, IndexedDB, readable cookies, URLs, logs or error payloads.

## Gate
Audit production configuration for any fixture adapter, fake identity/scope, placeholder or hidden `501` path. None may be silently active.

Also verify:

- production configuration fails closed when backend/OIDC settings are missing or malformed;
- OIDC endpoint handling uses standards-based discovery for the supported generic profile;
- HTTPS/proxy/cookie/CSP/CSRF requirements from P1 are active;
- every async mutation shown as successful corresponds to authoritative O3K Operation/resource truth;
- bounded pagination is used for inventories and Operations.

## Evidence
Create `docs/engineering/o3k-production-evidence.md` with exact O3K/Araf/IdP/provider versions, topology, TLS profile, commands, test identities/scopes, successful and failed journeys, isolation evidence, browser token-custody evidence, operator evidence, known deviations and exact CI/test results.

## Acceptance
Exactly one verdict: `GO — O3K PRODUCTION CONVERGED` or `NO-GO`.

Do not issue GO merely because P12-IAM or individual P2 issues passed. This gate is the integrated production-profile proof.
