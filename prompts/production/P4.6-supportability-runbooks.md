# P4.6 — Supportability, operator docs and runbooks

## Goal
Make Araf operable by engineers who did not implement it.

## Deliver
- installation/configuration guide;
- production security guide;
- O3K backend guide and supported-contract matrix;
- OpenStack backend profile/configuration/capability guide;
- authentication/session troubleshooting;
- incident runbooks for BFF unavailable, backend unavailable, auth failure, Operation stuck/failing, CompatibilityOperation unknown, quota/service-discovery issues;
- observability/correlation guide;
- upgrade/rollback and backup/recovery guidance for Araf-owned durable state such as sessions/compatibility-operation journal;
- support bundle guidance that redacts credentials;
- known limitations and non-goals.

## Acceptance
A separate engineer can deploy, diagnose common failures and perform upgrade/rollback from the docs without requiring undocumented maintainer knowledge.
