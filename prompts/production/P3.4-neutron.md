# P3.4 — Neutron Networking adapter

## Goal
Support the network concepts required by the Araf tenant VM journey through real Neutron APIs.

## Implement
- capability-map supported network, subnet, port and security-group concepts;
- list/show and the minimum create/update/delete flows required by the accepted Araf profile;
- provide network selections required by VM creation;
- preserve project/region isolation and backend provenance;
- map Neutron provisioning/status truth into generic Araf statuses without fabricating health;
- surface service-specific diagnostics only in bounded advanced/error contexts;
- use server-side pagination/filtering where available and document limitations.

## Non-goal
Do not recreate Horizon topology or expose Neutron vocabulary throughout normal tenant navigation.

## Acceptance
A tenant can discover/select/manage the supported Araf network resources and use them in VM creation on a real OpenStack cloud.
