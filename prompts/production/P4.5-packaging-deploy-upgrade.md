# P4.5 — Packaging, deployment, configuration, upgrade and rollback

## Goal
Make Araf installable and upgradeable as a product rather than a developer workspace.

## Implement
- reproducible versioned OCI images for Tenant Console/BFF and Operator Console/BFF as appropriate;
- supported reference deployment artifacts, preferably Kubernetes/Helm while keeping container contracts usable outside Kubernetes;
- explicit config schema/validation for backend type, endpoints, OIDC, sessions, TLS/proxy assumptions and capabilities;
- secret references/externalization; no secrets in images/config examples;
- health/readiness probes and resource recommendations;
- version/build metadata visible to operators;
- documented compatibility matrix for Araf version vs supported O3K API and OpenStack profile versions;
- test upgrade and rollback between at least the previous supported release/RC and candidate;
- ensure configuration changes fail clearly instead of silently defaulting to insecure/fixture modes.

## Acceptance
A clean environment can install the release from documented artifacts, upgrade, validate health, and roll back without rebuilding source.
