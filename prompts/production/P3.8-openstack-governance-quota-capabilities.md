# P3.8 — OpenStack governance, quotas and capability mapping

## Goal
Make the OpenStack-backed UI honest about what the caller and deployed services can actually do.

## Implement
- derive service availability from Keystone catalog plus adapter capability probes;
- map effective project/session capabilities conservatively; do not infer broad authorization from role names alone;
- expose Nova/Neutron/Cinder quota limits/usage for supported profile using their authoritative APIs;
- support project/user information needed by tenant governance where Keystone permits it;
- capability-hide unsupported IAM/admin functions instead of simulating O3K IAM;
- document where OpenStack authorization cannot be precomputed and rely on server-side enforcement;
- add negative authorization tests.

## Acceptance
The UI advertises only supported services/actions, quota views are real, and no O3K-specific governance semantics are falsely projected onto OpenStack.
