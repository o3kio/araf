# P2.7 — Authoritative quota, metering, usage and bounded cost awareness

## Goal
Make usage views truthful and scalable without turning Araf into billing/accounting.

The #45 discovery workstream is complete and O3K northbound convergence #907 is
complete at `21fe687c387a04f107b6e87fac04060b1c28e449`. Native quota and the
bounded metering definitions/usage contracts are merged and authoritative;
Araf consumes those frozen contracts through its BFF adapter. No new O3K API
may be introduced for this issue unless a reproducible violation of a merged
contract is demonstrated.

## Implement
- consume authoritative quota and meter definitions;
- bounded project/resource usage queries by time range;
- units, aggregation periods and locale-safe formatting;
- cost estimate only if authoritative pricing metadata exists;
- explicit unavailable state when price data does not exist;
- server-side bounded queries, no browser resource counting as billing truth.

Fixture/static usage and pricing data is development/test-only. Production must
never silently fall back to fixtures when O3K quota or metering discovery is
missing, malformed, unavailable or unsupported. O3K does not currently expose
pricing metadata, so Araf must show an explicit unavailable cost state rather
than fabricate currency values.

## Non-goals
Invoices, tax, payment, collections and accounting ledgers.

## Acceptance
Usage/quota/cost screens contain only authoritative values with clear units/time ranges and no fixture or fabricated price data in production.
