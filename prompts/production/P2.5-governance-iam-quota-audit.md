# P2.5 — Real tenant governance, IAM, quota and audit

O3K northbound convergence #907 is complete and #45 discovery is merged.
Native IAM, quota, audit and scope contracts at the converged O3K commit are
authoritative and frozen for this workstream. Araf consumes those contracts;
it must not invent or redesign O3K APIs. Tenant IAM views are implemented only
where a canonical tenant contract exists; otherwise they are capability-hidden.

## Goal
Replace governance fixtures/placeholders with the supported authoritative O3K subset.

## Implement as supported upstream
- current users/principals and memberships;
- role/capability bindings without frontend role-name inference;
- service accounts/workload identities if canonical;
- project membership/context management;
- quota limits and consumption;
- audit-event collection/detail with actor/action/target/scope/result/correlation;
- server-side authorization and negative cross-scope tests.

Quota and audit use the native `/quota` and `/audit` routes through the BFF.
The operator-only governance IAM routes are not tenant APIs and must not be
projected into the tenant console.

## Rules
Audit is not Operation. Do not create a second IAM model or use OpenStack compatibility DTOs as native O3K truth.

## Acceptance
Every production-visible governance view is backed by O3K or capability-hidden. Cross-project and unauthorized mutations are rejected by the server and verified end-to-end.
