# P1.3 — Protect `main`

## Goal
Make the repository quality gates enforceable rather than advisory.

## Current-state finding

Araf `main` is currently protected and names frontend, Rust and `browser E2E (Chromium)` as required checks. However, the current CI workflow does not emit the browser job. Therefore protection configuration exists, but the end-to-end policy is not yet accepted until P1.2 repairs the check producer and a real PR proves the normal merge path.

## Implement/Configure
- preserve or strengthen `main` protection / repository ruleset;
- require pull requests for normal changes;
- after #38, require the exact current frontend, Rust and browser E2E checks actually emitted by CI;
- remove stale required-check names that no workflow can produce;
- block force-push and branch deletion;
- require branches to be current where this is reliable for the repository workflow;
- establish the minimum review policy sustainable by current maintainers;
- document any emergency/admin bypass as exceptional and auditable;
- verify protection against a real pull request rather than configuration inspection alone.

## Acceptance
A normal PR with a failing or missing required gate cannot merge, while a PR with all intended produced checks can merge through the normal reviewed path. Direct unreviewed normal development into `main` is prevented. Document the final rule names and exact check contexts.
