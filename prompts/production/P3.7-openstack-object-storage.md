# P3.7 — Optional OpenStack object-storage capability profile

## Goal
Provide object-storage support when the target OpenStack deployment actually offers it, without making Swift/S3 mandatory for the core profile.

## Implement
- capability detection from configured catalog/endpoints;
- Swift support for bucket/container/object metadata flows required by the Araf Object Storage MVP surface where available;
- optionally support an explicitly configured S3-compatible endpoint (for example RGW S3) behind a separate adapter capability;
- credentials remain server-side and scoped appropriately;
- hide Object Storage navigation when neither supported capability exists;
- never assume Swift and S3 semantics are identical; expose only the common supported product contract and preserve advanced differences where necessary.

## Acceptance
Supported object-storage deployments work through Araf, unsupported clouds have no dead/fake Object Storage surface, and the core OpenStack profile remains usable without this optional capability.
