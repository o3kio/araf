# P2.4 — Canonical O3K Operations Center

## Goal
Make Operations fully real and production useful across page reloads, resources and global/project views.

## Implement
- consume authoritative O3K Operation list/show APIs;
- server-bounded pagination/filtering/order;
- scope-safe queries and foreign-operation non-disclosure;
- mutation-to-operation linkage for every supported async action;
- refresh/poll or authoritative event stream according to O3K contracts;
- structured failure, Problem Details, request/correlation IDs and related resources;
- deep links from resource to Operation and Operation to resource;
- distinguish Operation from Audit.

## Forbidden
No invented orchestration timeline, browser-memory completion state or `202 => success` behavior.

## Acceptance
A running/failed/succeeded operation survives navigation/reload and is reconstructed from O3K truth; global Operations shows real bounded project activity.
