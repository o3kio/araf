# P3.9 — OpenStack production support-profile E2E gate

## Goal
Prove that OpenStack is a real supported Araf backend, not a collection of adapter unit tests.

## Environment
Use a representative real OpenStack deployment matching the documented support
profile. OpenStack certification is version-specific: the current reference
target is **OpenStack 2026.1 Gazpacho (SLURP)** with matching
`stable/2026.1` Kolla-Ansible 22.x tooling and matching 2026.1 service images.
Do not use `2026.1 or later` as a compatibility claim; each later OpenStack
series requires its own P3.9 evidence before it is advertised as supported.

Existing 2024.2 and 2025.1 runs may be retained as historical/transitional
compatibility evidence, but they do not certify the 2026.1 target. In
particular, a run using Kolla-Ansible 19.x with 2025.1 images is cross-series
and must not be described as matched-toolchain certification.

## Required common journeys
- authenticate and select project/region;
- discover services/capabilities;
- list/create/show/start/stop/delete VM;
- select Glance image/flavor;
- use required Neutron network flow;
- list/show/manage supported Cinder volume flow;
- observe CompatibilityOperations through success and real failure;
- inspect real quotas;
- optional Object Storage journey only when capability enabled;
- cross-project/unauthorized negative access.

## Parity rule
Reuse the same high-level Araf browser journey definitions used for O3K wherever semantics overlap. Backend adapters may differ, React product flow should not.

## Evidence
Create `docs/engineering/openstack-production-evidence.md` containing tested OpenStack versions/services, capability matrix, known bounded deviations and exact validation results.

## Acceptance
Exactly one verdict for the **current target release**: `GO — OPENSTACK PROFILE SUPPORTED` or `NO-GO`.
