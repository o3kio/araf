# P1.4 — Production deployment security and fail-closed mode

## Goal
Turn the dev-server topology into an explicitly secure production deployment model.

## Implement
- define production versus development configuration modes;
- production browser entry must be HTTPS; document TLS termination ownership and trusted proxy assumptions;
- verify Secure/HttpOnly/SameSite cookie behavior, logout, expiry and session-fixation defenses;
- enforce/strengthen CSP, origin and CSRF behavior; remove avoidable `unsafe-inline`/unsafe assumptions where feasible;
- configure HSTS at the TLS-terminating boundary where appropriate;
- production upstream mode must fail closed when a required backend capability is unavailable;
- fixtures, fake identity/scope and fixture resources must never silently substitute in production;
- remove or capability-hide development-only fake/placeholder navigation in production;
- add deployment/security tests for forwarded headers, HTTPS assumptions and cookie attributes.

## Non-goal
Do not implement missing O3K identity/control-plane semantics inside Araf.

## Acceptance
A documented reference deployment proves HTTPS browser trust, secure BFF sessions, strict production configuration and zero silent fixture fallback.
