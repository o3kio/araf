# P1.4 — Production deployment security and fail-closed mode

## Goal
Turn the dev-server topology into an explicitly secure production deployment model.

## Current-state findings

P12-IAM has removed the upstream identity blocker, so this issue must no longer wait on an invented Araf IAM workaround. The remaining defects are Araf-side production-mode/configuration concerns.

At the current baseline:

- BFF session cookies are `Secure`, `HttpOnly` and `SameSite=Lax`;
- production OIDC/BFF code exists;
- however `BffConfig::from_env()` still maps a missing or unrecognized `ARAF_UPSTREAM_ADAPTER` to `Fixture`;
- therefore a production deployment can silently become a fixture deployment through configuration omission/typo unless an explicit production mode forbids it.

## Implement
- define explicit production versus development/test configuration modes;
- production browser entry must be HTTPS; document TLS termination ownership and trusted proxy assumptions;
- verify Secure/HttpOnly/SameSite cookie behavior, logout, expiry and session-fixation defenses;
- enforce/strengthen CSP, origin and CSRF behavior; remove avoidable `unsafe-inline`/unsafe assumptions where feasible;
- configure HSTS at the TLS-terminating boundary where appropriate;
- in production mode require an explicit supported upstream adapter; missing, empty, unknown or malformed adapter values must fail startup rather than select `Fixture`;
- production O3K mode must fail closed when required O3K capability/configuration is unavailable;
- fixtures, fake identity/scope and fixture resources must never silently substitute in production;
- production OIDC/O3K URL/client configuration must be validated at startup rather than relying on development localhost defaults;
- remove or capability-hide development-only fake/placeholder navigation in production in coordination with #43;
- add deployment/security tests for forwarded headers, HTTPS assumptions, cookie attributes, missing/invalid production config, and explicit refusal of fixture fallback.

## Non-goals
- do not reimplement O3K P12-IAM in Araf;
- do not add an Araf-specific identity authority;
- provider-neutral OIDC discovery/client interoperability is closed in #44 rather than by adding Keycloak-specific production configuration here.

## Acceptance
A documented reference deployment proves HTTPS browser trust, secure BFF sessions, strict startup validation and zero silent fixture fallback. A deliberately missing or misspelled production backend configuration must fail startup deterministically.
