# P1.2 — Browser E2E and visual shell regression CI

## Goal
Make real browser behavior a required merge signal so semantic/unit green builds cannot regress into an unstyled or unusable console.

## Current-state finding

At the post-P12-IAM baseline, Araf branch protection lists a required check named `browser E2E (Chromium)`, but `.github/workflows/ci.yml` emits only the frontend and Rust jobs. This is not a completed protection state: a required-check name without a producing workflow is stale/broken governance, not browser coverage.

Treat this mismatch as the first defect to fix.

## Implement
- add a GitHub Actions job whose stable check name matches the repository protection policy (`browser E2E (Chromium)`) or intentionally update both workflow and protection to one reviewed canonical name;
- run the existing Playwright suite on pull requests using the deterministic fixture harness;
- pin/install Chromium deterministically and cache only safe reusable layers;
- add Tenant and Operator shell smoke coverage at representative desktop and narrow viewports;
- verify navigation active state, scope controls, search, focus/keyboard traversal and non-default shell layout;
- prove omitting the shell stylesheet causes a deterministic failure;
- retain trace/screenshot artifacts on failure;
- keep first-pass assertions semantic/computed-style based rather than broad brittle pixel diffs;
- prove the produced check appears on a real PR and is consumable by branch protection.

## Preserve
No trust-boundary, backend, fixture-production, resource-runtime or O3K semantic changes.

## Acceptance
- the browser E2E check is actually emitted on PRs;
- `pnpm e2e` is executed by CI;
- existing E2E remains green;
- the known raw-shell regression is caught;
- failures are diagnosable from artifacts;
- repository protection can require the exact produced check without a stale/missing status context.
